# #76: перший Python → my-lisp vertical slice

## Мета

Замістити `scripts/generate-meta-semantic-registry.py` Lisp-owned генератором без зміни semantic authority або generated projection.

## Межа authority

- `lib/surface/semantic-registry.lisp` лишається єдиним джерелом identity/surface truth.
- Генератор володіє лише projection mechanics.
- Lisp читає registry структурно через `read-file` + `read-all`; текстовий regex-парсер більше не потрібний.
- `stable` і `compatibility-only` surfaces допускаються; `candidate`, `missing`, `—` та reader-only exact apostrophe відкидаються.
- Однакове spelling для тієї самої identity дедуплікується; колізія spelling між різними semantic IDs fail-closed.

## Поведінковий контракт

1. Default mode регенерує `lib/generated/meta-semantic-registry.lisp` детерміновано.
2. `--check` порівнює committed projection з щойно згенерованим текстом і завершується ненульово при drift.
3. Generated bytes мають збігатися з чинною Python-проекцією, окрім provenance-рядка `Generator`, який після cutover називає `.lisp` generator.
4. Negative self-test доводить fail-closed collision handling і reader-only apostrophe exclusion.

## TDD / cutover

Спочатку CI gate викликає ще неіснуючий Lisp generator (RED). Потім додається мінімальна реалізація (GREEN). Після parity Python generator видаляється, усі активні CI references перемикаються на Lisp, а stale references оновлюються.
