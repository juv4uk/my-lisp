# Історичний дизайн компактної української поверхні `uk`

> **Статус: історичний design record, звірений із `main` 2026-09-14.**
> Документ зберігає правила й rejected alternatives зі старої naming-роботи.
> Він не ратифікує жодного spelling. Чинні `uk`/`ukr` і їхні статуси визначає
> тільки `lib/surface/semantic-registry.lisp`.

## Дві українські поверхні — дві різні задачі

Дизайн розділив ролі навмисно:

```text
uk  = компактне українське ім'я, зручне для набору й інтуїтивного читання
ukr = повне українське ім'я, максимально явне й описове
```

Обидві форми є peer spellings одного numeric semantic ID. Жодна з них не є
identity і не створює окремої реалізації.

Компактність тут не означає «мінімум символів». Основна вимога: україномовний
програміст має мати шанс зрозуміти дію без запам'ятовування таблиці кодів.

## Вибраний спосіб скорочення

Розглядалися три підходи.

### 1. Просте обрізання кореня

```text
помножити  → множ
обчислити  → обчис
підставити → підст
```

Плюс: системність і видимий зв'язок із повною формою. Мінус: у складених назвах
послідовність обрізаних коренів швидко стає важкою для читання.

### 2. Структурне скорочення + консервативне обрізання — вибраний напрям

Спочатку прибирається граматичний шум і формується стабільний порядок
семантичних частин; лише потім довгі корені можна скоротити, якщо вони
лишаються впізнаваними.

Приклади історичного напряму:

```text
довжина-вектора             → вектор-довж
перший-символ-тексту        → текст-перш
встановити-елемент-вектора! → вектор-встан!
помножити                    → множ
```

Для object operations корисною виявилася форма:

```text
<object>-<operation-or-property>
```

Наприклад:

```text
довжина-тексту   → текст-довж
довжина-вектора  → вектор-довж
отримати-з-карти → карта-отрим
вставити-в-карту → карта-встав
```

### 3. Вільні синоніми — не як автоматичне правило

Наприклад, перетворити
`елемент-списку-за-індексом` на `за-номером` може бути коротко й навіть
зрозуміло, але з компактної форми вже важко відновити вихідну конструкцію.
Тому вільний синонім не повинен автоматично ставати `uk stable`; він потребує
окремого review як alias/convenience spelling.

## Основні правила, які варто зберегти

### Повна форма раніше за компактну

Компактний кандидат оцінюється відносно конкретного `ukr` spelling. Якщо повна
форма ще спірна, скорочувати її передчасно.

### Корінь має лишатися впізнаваним

Прийнятний напрям:

```text
помножити   → множ
обчислити   → обчис
підставити  → підст
уніфікувати → уніф
```

Неприйнятний за замовчуванням:

```text
помножити  → пмж
обчислити  → бчс
підставити → пдст
```

Тобто compact surface не повинна перетворюватися на consonant code.

### Спочатку структурне скорочення

Слова на кшталт `у`, `із`, `за`, `для`, `від`, `до` можна прибирати лише там,
де семантичний зв'язок однозначно відновлюється з порядку частин. Якщо
прийменник несе суттєвий напрям або роль, його не слід видаляти механічно.

### Добрі короткі слова не треба псувати

Такі форми, як `атом?`, `список`, `пара`, `корінь`, `остача`, `частка`,
`нехай`, можуть лишатися цілими. Штучне скорочення на один-два символи не є
виграшем.

### `?` і `!` несуть семантичну інформацію

Predicate marker `?` і mutation marker `!` не можна викидати заради довжини.

### Без Latin-layout стрибків

Компактний `uk` успадковує той самий UX-принцип, що й `ukr`: публічні
українські identifiers не повинні вимагати ASCII Latin letters.

### Абревіатури — лише після доказу зрозумілості

Форми типу `всч`, `нс`, `мс` дуже короткі, але без попереднього знання є
кодами. Вони не отримують перевагу лише через малу довжину.

### Один spelling не може мовчки означати два semantic ID

Collision detection має бути numeric-ID based і fail-closed. Якщо два повні
імені природно стискаються до одного кандидата, хоча б один кандидат треба
переглянути.

### `uk == ukr` — нормальний результат

Коли повна форма вже коротка й природна, не потрібно вигадувати інше компактне
слово заради формальної різниці колонок.

## Історична promotion-модель

Під час naming-роботи пропонувалася дисципліна:

```text
proposed
  ↓
mechanically-valid
  ↓
blind-test
  ↓
clear | revise | ambiguous | reject
  ↓
stable
```

Ключова ідея тут важливіша за конкретний старий workflow: **кандидат не стає
мовною authority лише тому, що його записав автор**. Механічні перевірки й
користувацьке декодування мають передувати promotion.

Після ратифікації старе spelling, якщо потрібна сумісність, повинно жити як
explicit compatibility alias, а не як друга identity.

## Blind-decoding як захист від «мови для автора»

Старий дизайн вимагав показувати учаснику лише compact form і просити:

1. очікувану повну форму;
2. очікувану семантичну дію;
3. рівень упевненості.

Це корисний принцип навіть якщо конкретний historical protocol більше не є
активним gate. Він відділяє «мені подобається це скорочення» від доказу, що
воно справді читається іншими людьми.

## Rejected / high-risk alternatives

Цей набір треба зберегти саме як негативний design capital:

| Повна або зрозуміла форма | Ризикований compact | Чому слабко |
|---|---|---|
| `помножити` | `пмж` | consonant code |
| `обчислити` | `бчс` | vowel-stripped code |
| `перший-символ-тексту` | `пст` | initials потребують запам'ятовування |
| `встановити-елемент-вектора!` | `вев!` | втрачені лексичні корені |
| `монотонний-час-у-наносекундах` | `мнс` | stacked abbreviation |
| `поточний-всесвітній-координований-час` | `всч` | acronym без самодекодування |
| `мілісекунди-із-наносекунд` | `мс-нс` | unit initials замість слів |
| `прочитати-з-мережевого-з'єднання` | `мрж-чт` | кілька непрозорих обрізань |

Окремо історично обговорювалися привабливі «людські» альтернативи на кшталт
`плюс`. Їх не слід плутати з authority: навіть інтуїтивний синонім може бути
лише candidate/alias, доки його не ратифіковано для конкретного numeric ID.

## Приклади кандидатів, що були корисні для досліду

Стара гілка тримала набір реальних registry-прикладів не як production names,
а як матеріал для перевірки правил. Серед них:

```text
помножити                         → множ
приєднати                         → приєд
елемент-списку-за-індексом        → список-елем
довжина-тексту                    → текст-довж
перший-символ-тексту              → текст-перш
прочитати-усе                     → прочит-усе
довжина-вектора                   → вектор-довж
елемент-вектора                   → вектор-елем
прочитати-з-мережевого-з'єднання  → мережа-прочит
прочитати-файл                    → файл-прочит
```

Частина прикладів навмисно була ризикованою. Їхня цінність — не в тому, щоб
повернути їх у registry, а в тому, що вони показали межу між читабельним
скороченням і кодовою мовою.

## Що чинне сьогодні

На `main` 2026-09-14:

- numeric semantic ID лишається identity;
- `uk` і `ukr` — peer human surfaces;
- semantic registry — authority;
- цей документ не промотує жодного candidate;
- конкретні чинні назви треба читати лише з
  `lib/surface/semantic-registry.lisp`.
