# Karatsuba multiplication для Magnitude — дизайн (OPT наступний крок)

**Статус:** DRAFT · 2026-08-24 · Vyasa · НЕ РЕАЛІЗОВАНО

## Проблема
Після прибрання gcd-вузьких місць глибокі exact-ланцюги лімітуються
schoolbook mul: O(n²) над limb'ами base-2^32. n=800 ланцюг ≈ 320s;
заміри вказують домінанту великих mul у `checked_add` (a·d', c·b').

## Алгоритм
Для |limbs| ≥ THRESHOLD (стартово 32):
```
m = ceil(max/2)
al, ah = split(a, m); bl, bh = split(b, m)
z0 = al*bl; z2 = ah*bh; z1 = (al+ah)*(bl+bh) − z0 − z2
result = z2·B^(2m) + z1·B^m + z0      (B = 2^32)
```
Рекурсія до THRESHOLD, далі schoolbook. Складність O(n^1.585).

## Потрібні примітиви Magnitude (усе вже є або тривіально)
- add (є), sub з передумовою a≥b (є; у Каратубі гарантовано бо сума ≥ доданки)
- розріз по індексу (splice/split — дешево)
- конкатенація зі зміщенням (splice нулів на молодші позиції — як shl_assign limbs)

## Верифікація (обовʼязково ДО merge)
1. Диференційний детермінований корпус vs schoolbook: нерівні розміри,
   нулі, ±межі THRESHOLD, повний діапазон limb значень (включно 0xFFFFFFFF)
2. Власність-тест: множення комутативно/асоціативно на випадкових парах
3. Rational-регресії: mccarthy arithmetic_promotes + conformance fixtures
4. Бенчмарк rational-chain n=400/800 у тихому вікні; очікування −30…−60%
   саме на глибоких n (де mul домінує)

## Ризики
- Помилки переносів на стиках частин → ловиться диф-корпусом
- Алокаційний тиск від проміжних сум → виміряти; за потреби
  reuses буферів (Out-параметр) як друга ітерація
- Не чіпати TAG_FIXNUM швидкий шлях i64 (він вище за рівнем)
