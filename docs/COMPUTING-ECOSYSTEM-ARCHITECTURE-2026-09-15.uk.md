# Архітектура обчислювальної екосистеми — потоки й залежності (2026-09-15)

![Моя обчислювальна екосистема — архітектура, залежності та потік даних](architecture/computing-ecosystem-architecture.png)

Схема архітектури повного стеку, авторства власника: від семантики Lisp до
заліза, з явними межами володіння на кожному рівні. Цей репозиторій
(`my-lisp`) — це шар **my-lisp (Мова та семантика)** на схемі: він володіє
значенням (evaluator, таблиця функцій, Canon, стандартна бібліотека) і
виробляє Machine Contract, що визначає Lisp-owned машинні форми — активна
вітка `#175 → #176 → #177` (імпорт XED-доказів → покриття encoder-а →
композиційні машинні атоми).

Повний стек, згори донизу:
- **Користувач / розробник** — пише Lisp-програми, експерименти, тести,
  працює з агентами.
- **my-lisp (Мова та семантика)** — цей репозиторій.
- **CML (компілятор для My Lisp)** — споживає семантику Lisp і перевірені
  CPU-профілі, щоб згенерувати цільовий код; ніколи не перевизначає
  значення мови.
- **Target Runtime / OS** (напр. `wsm-os-lisp`) — реалізує ABI і володіє
  конкретним доступом до пристроїв (MMIO, PCI, syscalls).
- **Залізо** — реальний CPU/пристрої/FPGA, на яких виконується runtime.
- **Зовнішні джерела** (документація виробників CPU, стандарти,
  дослідження, зовнішні оракули — напр. Intel XED для `#175`) — лише
  read-only доказ/довідка, ніколи не семантична влада (див. `#150`).

Ця схема — знімок наміру, а не сама по собі авторитетний документ:
`juv4uk/ecosystem#7` (жива крос-репо карта) і власний issue цього репо
`[REFERENCE · KEEP OPEN] Ecosystem map for my-lisp agents` (`#183`)
лишаються авторитетним, оновлюваним на місці джерелом істини про поточне
володіння та межі.
