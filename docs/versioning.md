# Versioning and inherited history · Версіонування та успадкована історія · Versionierung und übernommene Historie

## English

This repository was extracted from [`my-idea`](https://github.com/juv4uk/my-idea) via `git filter-repo`, keeping only the files that belong to the my-lisp language (see [`PLAN.md`](../PLAN.md) for the extraction plan). The extraction preserves per-file commit history for everything that stayed, so the log still shows how the language evolved inside the IDE project before the split — including commits and tags whose messages describe IDE-only work. They are historical provenance, not a statement that IDE code is part of this repository; the actual IDE files are gone.

Release tags from before the split are immutable and were not deleted; do not reuse an occupied version number. `crates/my-lisp` and its sibling crates version independently starting at `0.1.0`, regardless of what tag numbers exist in the inherited history.

Release tags in this repository use the prefix `l` (for example `l0.9.2`), not the inherited `v` prefix — a deliberate choice, so a new tag can never collide with one of the pre-split `v0.1.0`–`v0.9.0` tags still sitting in the inherited history. `.github/workflows/release.yml` triggers on `l*`, not `v*`.

## `language-contract.my`: a second, independent version axis (2026-08-10)

A third repository joined the ecosystem: [`cml`](https://github.com/juv4uk/cml), an AOT compiler from my-lisp source directly to `fpga-lisp`'s ISA (not a runtime `eval` on hardware, like `fpga-lisp`'s own current bootstrap — compilation ahead of time, on a PC, emitting fixed assembly). With three repositories now moving at different paces, the user proposed a synchronization architecture and it's recorded here in full, since PLAN.md's own entry (item 24) only summarizes it.

**The problem with one shared version number.** Tagging all three repositories with the same number (`my-lisp v0.15.0`, `fpga-lisp v0.15.0`, `cml v0.15.0`) creates a false dependency: `my-lisp` can ship ten purely additive, library-level, or dedup releases (exactly what happened in this session — `quotient`/`mod`, `nth`/`assoc`/`member?`, `cddr`/`cadddr`/`fifth`, `write-file-bytes`) while the actual *semantic contract* the language promises never moves at all — and conversely, `fpga-lisp`'s ISA can change (a new opcode encoding, a different register convention) without any of `my-lisp`'s own semantics changing. Compatibility between the three is a **pair** of versions (language contract, ISA version), not one shared number, and a commit SHA is a different thing again — SHA is "what we actually tested," a contract version is "what's semantically compatible."

**The architecture, as proposed:**
- The language contract moved from `0.1` to `1.0` on 2026-08-11 when bare integer literals stopped silently rounding above 2^53 and became arbitrary-precision exact values. This is the contract axis only, not a crate release or project-maturity declaration.
- `my-lisp` versions its **LANGUAGE CONTRACT** — [`language-contract.my`](../language-contract.my) at the repo root, covering exactly axiom Level 1 (CORE SEMANTICS) and Level 2 (LANGUAGE CONTRACT) from [`docs/language-core-axioms.md`](language-core-axioms.md) — deliberately not Level 3 (ecosystem/library conformance: `core.my`, `unify.my`, `reason.my`, `knowledge.my`, CLIPS import, literate markdown), which changes independently and far more often. `major` bumps on a breaking semantic change (an existing well-formed program could now observe different behavior — e.g. the exactness model, item 10, had this file existed then); `minor` bumps on an additive, backward-compatible one (e.g. `\r` joining `\n`/`\t` as a real string escape, same day this file was introduced). A new `core.my` function, a bugfix, a new Rust primitive inside an already-Level-2-covered capability class (`write-file-bytes` is the same "file I/O" class `read-file`/`write-file` already established) — none of these bump it. Starts at `0.1` on 2026-08-10, not retroactively numbered for the project's earlier semantic history.
- `fpga-lisp` should version its **ISA** separately from its own implementation version (an internal heap optimization shouldn't bump the ISA version; a changed `CONS` opcode encoding should) — via an `ISA.md` plus a machine-readable manifest. Out of scope for this repository; proposed to the `fpga-lisp` session, not yet implemented there as of this writing.
- `cml` should hold a `compatibility.my` pinning a `my-lisp` language-contract version, an `fpga-lisp` ISA version, and the specific tested SHAs of each — the file that actually says "this compiler build is known to work with contract 0.15 targeting ISA 0.4." Out of scope for this repository, and `cml` runs in Antigravity IDE rather than a CCD session this repository's own sessions can message directly — coordinating it is on the user, not something these two repositories' sessions can do to each other automatically.

**Three-tier CI, as proposed (not yet built anywhere).** Each repository stays self-sufficient (local CI needs no live network to the other two). A separate interface-CI job in `cml` checks out pinned known-good SHAs of `my-lisp` and `fpga-lisp` and runs compile → assemble → simulate → compare. A third, non-blocking integration-CI job tracks all three `main` branches' heads together and reports "ecosystem heads: compatible / incompatible" without gating ordinary development in any one repository — so `my-lisp`'s `main` can move ahead of `cml`'s support for it without breaking anyone's day-to-day CI.

**The guiding principle, in the user's own words:** *"Синхронізувати треба не репозиторії. Синхронізувати треба їхні межі."* ("What needs synchronizing isn't the repositories — it's their boundaries.") The three projects' code should be free to move at different speeds; only the contracts between them should refuse to let that happen unnoticed.

## `language-contract.my`: друга, незалежна вісь версіонування (2026-08-10)

До екосистеми приєднався третій репозиторій: [`cml`](https://github.com/juv4uk/cml) — AOT-компілятор із джерела my-lisp напряму в ISA `fpga-lisp` (не рантайм-`eval` на залізі, як поточний bootstrap `fpga-lisp`, — компіляція наперед, на ПК, з фіксованим асемблером на виході). Коли три репозиторії рухаються з різною швидкістю, користувач запропонував архітектуру синхронізації — записана тут повністю, бо власний запис у `PLAN.md` (пункт 24) лише підсумовує її.

**Проблема одного спільного номера версії.** Позначення всіх трьох репозиторіїв однаковим номером (`my-lisp v0.15.0`, `fpga-lisp v0.15.0`, `cml v0.15.0`) створює фальшиву залежність: `my-lisp` може випустити десять суто адитивних, бібліотечних чи dedup-релізів (точно те, що сталось цієї сесії — `quotient`/`mod`, `nth`/`assoc`/`member?`, `cddr`/`cadddr`/`fifth`, `write-file-bytes`), поки сам семантичний контракт мови взагалі не зрушить — і навпаки, ISA `fpga-lisp` може змінитись без жодної зміни семантики `my-lisp`. Сумісність між трьома — це **пара** версій (language contract, ISA-version), не один спільний номер, а SHA коміту — окрема річ узагалі: SHA — це "що ми реально перевірили", версія контракту — "що семантично сумісне".

**Архітектура, як запропоновано:**
- Language contract перейшов із `0.1` на `1.0` 2026-08-11, коли голі цілі literal-и перестали округлюватись понад 2^53 і стали точними довільної розрядності. Це лише вісь контракту, не реліз crate і не заява про зрілість усього проєкту.
- `my-lisp` версіонує свій **LANGUAGE CONTRACT** — [`language-contract.my`](../language-contract.my) у корені репо, покриває рівно Рівень 1 (СЕМАНТИКА ЯДРА) і Рівень 2 (КОНТРАКТ МОВИ) з [`docs/language-core-axioms.md`](language-core-axioms.md) — свідомо не Рівень 3 (екосистемна/бібліотечна конформність), яка змінюється незалежно й значно частіше. `major` піднімається на breaking-зміні семантики; `minor` — на адитивній, зворотносумісній. Нова функція в `core.my`, багфікс, новий Rust-примітив у вже покритому Рівнем 2 класі можливостей — жодне з цього версію не піднімає. Стартує з `0.1` 2026-08-10, не пронумерований ретроактивно за всю попередню історію.
- `fpga-lisp` мав би версіонувати свій **ISA** окремо від власної версії реалізації — через `ISA.md` плюс машинно-читаний manifest. Поза межами цього репозиторію; передано в сесію `fpga-lisp`, ще не реалізовано там на момент цього запису.
- `cml` мав би тримати `compatibility.my`, що прив'язує версію language-contract `my-lisp`, версію ISA `fpga-lisp` і конкретні перевірені SHA обох. Поза межами цього репозиторію, і `cml` працює в Antigravity IDE, не в CCD-сесії, яку сесії цього репозиторію можуть напряму сповістити — координація цього лежить на користувачеві.

**Триярусний CI, як запропоновано (ще ніде не побудовано).** Кожен репозиторій лишається самодостатнім локально. Окрема interface-CI джоба в `cml` чекаутить зафіксовані відомо-робочі SHA `my-lisp` і `fpga-lisp` та проганяє compile → assemble → simulate → compare. Третя, не блокуюча integration-CI джоба стежить за головами всіх трьох `main`-гілок разом і повідомляє "ecosystem heads: compatible / incompatible", не блокуючи щоденну розробку в жодному з репозиторіїв.

**Провідний принцип, словами користувача:** "Синхронізувати треба не репозиторії. Синхронізувати треба їхні межі." Код трьох проєктів має право рухатися з різною швидкістю; лише контракти між ними не повинні дозволяти їм непомітно розійтися.
