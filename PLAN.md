## Крок 0 — узгодити з користувачем перед стартом

Не виконувати нижче нічого без явного підтвердження користувача на кожен великий крок (видалення файлів, переписування історії, публічний push). План — не мандат діяти автономно.

## Крок 1 — інструментарій для чистої історії

- Перевірити `git filter-repo --version`. Якщо відсутній — треба Python 3 (зараз недоступний у PATH, `python3`/`python` не знайдено) + `pip install git-filter-repo`, або `scoop install git-filter-repo` (у користувача вже є scoop у PATH).
- Без `git-filter-repo` можна зробити грубіше: залишити тільки потрібні файли одним великим комітом (втратити per-file історію для решти), або спробувати `git filter-branch` (повільний, вбудований, але офіційно deprecated).
- **Рекомендація:** дочекатись `git-filter-repo`, не робити "грубе" видалення, якщо користувач хоче зберегти історію crates/my-lisp.

Тести: `understand_is_a_produces_a_class_membership_fact`, `understand_is_without_article_produces_the_same_fact`, `understand_subject_verb_object_produces_a_relation_fact`, `understand_all_have_produces_a_universal_rule`, `understand_output_is_usable_directly_as_a_reason_rule` у `crates/my-lisp/tests/understand.rs`.

По дорозі виправлено два реальні `eq`-баги арності/типу (виявлені тестами, не здогадані): `clips-split-at-arrow` падала на `(eq (car body) '=>)`, коли `(car body)` — складений список (умова на кшталт `(planet ?x)`), і `clips-defrule->clauses` падала на `(eq conclusion 'none)`, коли `conclusion` — реальний (складений) висновок; обидва виправлено тим самим guard-паттерном `(atom ...)` перед `eq`, що й скрізь у проєкті. Тести: `clips_deffacts_becomes_zero_condition_clauses`, `clips_import_skips_unsupported_forms_without_erroring`, `clips_import_result_feeds_straight_into_defmodule`, `clips_defrule_converts_question_mark_variables_to_var_terms`, `clips_defrule_leaves_non_variable_arguments_untouched`, `clips_defrule_with_multiple_conditions_converts_all_of_them`, `clips_defrule_with_no_or_multiple_asserts_imports_as_no_clauses`, `clips_import_mixes_deffacts_and_defrule_into_one_usable_module` у `crates/my-lisp/tests/clips_import.rs`; нові Rust-примітиви — `symbol_to_string_and_back_round_trips`, `string_first_returns_a_one_character_string`, `string_rest_drops_exactly_the_first_character`, `symbol_to_string_rejects_a_non_symbol`, `string_rest_rejects_an_empty_string` у `crates/my-lisp/tests/mccarthy.rs`. Крок 3 зроблено — за консультацією з `private/mccarthy-principles.md` (п.1/п.3: чиста my-lisp, без нового capability boundary, замість відкриття файлового I/O для читання `.clp` з диска, що лишається окремим майбутнім рішенням): будь-яка кількість `(assert ...)` після `=>`, не лише одна. N тверджень з однією LHS стають N окремими clause, по одному на кожне твердження, усі з тим самим списком умов. Досі обмежено лише `assert` — правило, чия `=>`-сторона містить іншу CLIPS-дію (`printout`, `retract`, `modify`), імпортується як відсутність clause, тією самою політикою "пропустити, не впасти". Тести: `clips_defrule_with_no_asserts_imports_as_no_clauses`, `clips_defrule_with_multiple_asserts_produces_one_clause_per_assert` у `crates/my-lisp/tests/clips_import.rs`.

Крок 8 зроблено (перед вибором обсягу — перевірка без здогадки: CLIPS-правило з `not`, імпортоване через `clips-import`, коректно доводить і через `reason-in` (backward), не лише `forward-in` — Крок 6 справді дав спільну мову для обох рушіїв, без бага): **`deftemplate`**, іменовані слоти CLIPS. Факти my-lisp лишаються чисто позиційними (нема причини розширювати представлення лише щоб віддзеркалити CLIPS) — оголошений порядок слотів шаблону стає фіксованим позиційним порядком, у який конвертуються факти: `(deftemplate reading (slot sensor) (slot value))` + `(reading (value 98) (sensor probe1))` → `(reading probe1 98)`, незалежно від порядку слотів у самому факті. Дво-прохідний, чисто функціональний підхід (`clips-templates-from-forms` сканує весь список форм наперед, будує alist `(назва . (слот1 слот2 ...))`) — не робочий мутабельний реєстр. Застосовується до конвертації термів **перед** конвертацією `?x`-змінних (порядок має значення: спершу репозиціювання за іменем слота, тоді підстановка `(var x)` для значень-змінних), і в `deffacts`, і в умовах/висновках `defrule` (з рекурсією крізь `not`-обгортку). Виявлено й підстраховано реальний крайовий випадок під час написання тестів: якщо позиційний факт випадково має ту саму назву, що й непов'язаний `deftemplate` (суперечливий, неправильно сформований CLIPS-вхід), `clips-lookup-slot-value` раніше падала на `car` не-пари; тепер деградує до "значення не знайдено" — той самий дух "пропустити, не впасти", що й у решті файлу. Тести: `clips_deftemplate_converts_named_slots_to_positional_order`, `clips_deftemplate_slot_order_holds_regardless_of_slot_order_in_the_fact`, `clips_deftemplate_applies_inside_defrule_conditions_and_conclusions`, `clips_deftemplate_works_end_to_end_through_forward_in` у `crates/my-lisp/tests/clips_import.rs`.

Крок 9 зроблено — знову спершу перевірка, не здогадка: правило `(defrule mass-rule (planet ?x) => (printout t "found planet " ?x crlf) (assert (has-mass ?x)))` — вкрай звичайний CLIPS-патерн (debug-вивід поряд із твердженням) — до цього кроку імпортувалось як **взагалі відсутність clause**, мовчки відкидаючи цілком представний `assert` лише через сусідній нешкідливий `printout`. `clips-drop-printouts` тепер фільтрує `printout`-форми перед перевіркою "чи всі решта — `assert`", тож `printout` більше не дискваліфікує правило. `retract`/`modify` і далі дискваліфікують — вони посилаються на факт за CLIPS fact-address, поняття, якого немає в моделі множини фактів цього проєкту (my-lisp порівнює факти структурно через `equal?`, не за ідентичністю), тож чесно імпортуються як відсутність clause, а не здогадка про непредставну семантику. Тести: `clips_defrule_with_printout_alongside_assert_still_imports_the_assert`, `clips_defrule_with_retract_still_imports_as_no_clauses` у `crates/my-lisp/tests/clips_import.rs`.

Крок 4 зроблено — той самий capability boundary, який свідомо відклали в Кроці 3, тепер узгоджений і зроблений явно: читання **справжнього** `.clp`-файлу з диска. `load` уже читає файл, але виконує кожну знайдену форму — саме неправильно для CLIPS-коду, чиї `defrule`/`=>` не є осмисленою my-lisp-командою для *виконання*, лише для читання як дані. Два нових Rust-примітиви: `read-file` (сирий текст файлу, без парсингу/виконання) і `read-all` (багатоформний відповідник `read` — парсить рядок у кожну форму верхнього рівня як дані; `read` падає, якщо рядок не рівно одна форма). `clips-import-file` у `lib/clips-import.my` — просто `(clips-import (read-all (read-file path)))`. Створено справжню CLIPS-фікстуру [`tests/fixtures/astronomy.clp`](../tests/fixtures/astronomy.clp) (не вигаданий приклад у тесті, а реальний файл на диску) для наскрізної перевірки. Тести: `read_all_parses_every_top_level_form_as_data`, `read_all_rejects_a_non_string` у `crates/my-lisp/tests/mccarthy.rs`; `clips_import_file_reads_and_imports_a_real_clp_file` у `crates/my-lisp/tests/clips_import.rs`.

Крок 5 зроблено — не за прямим запитом користувача обрати цей крок, а за консультацією з `private/mccarthy-principles.md` (п.4/п.7: чесність про межі, не тиха неправильна поведінка) і **перевіркою перед фіксом**, а не здогадкою: написав тестовий сценарій `(defrule bird-rule (animal ?x) (not (penguin ?x)) => (assert (bird ?x)))` і побачив, що `tweety` (тварина, не пінгвін) мовчки не стає `bird` — `match-conditions` у `lib/forward.my` унікує кожну умову буквально проти фактів, а жоден факт не має головою `not`, тож конвертована `(not (penguin (var x)))` завжди провалюється. Backward-chaining (`prove-goals`) коректно обробляє `not`, forward-chaining — ще ні; розширення `lib/forward.my` до negation-as-failure — окремий, більший крок (зміна самого рушія, не імпортера), тут не мається на увазі. Виправлено найчеснішим способом: `clips-defrule->clauses` тепер виявляє будь-яку умову `(not ...)` через `clips-any-not-condition?` і пропускає все правило (порожній список clause) — видимий, безпечний результат замість тихо зламаної бази знань. Тести: `clips_defrule_with_a_not_condition_is_skipped_not_silently_broken`, `clips_defrule_without_a_not_condition_still_imports_normally` у `crates/my-lisp/tests/clips_import.rs`.
